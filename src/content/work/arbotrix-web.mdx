```

  │
  ├─ Explores interactive 3D chassis preview (Lazy-loaded Spline canvas)
  │
  └─ Submits ROS 2 Internship Application
        │
        ▼ POST via Next.js Server Action
[BACKEND APPLICATION LAYER]
  │
  ├─ Zod Schema Validation (Input sanitization & phone format checks)
  │
  ├─ Prisma ORM Database Transaction
  │     │
  │     ▼ SQL INSERT
  │  [SUPABASE POSTGRESQL CLUSTER]
  │     └─ Enforces unique email constraint & records timestamp
  │
  └─ Resend Transactional Email Dispatch
        │
        ▼ SMTP Relay
     [STUDENT INBOX]
        └─ Delivers confirmation email with syllabus PDF attachment
```

## 05 / Key Technical Decisions & Performance Optimization

### 1. Lazy-Loading Heavy 3D Spline Canvases (LCP Protection)
- **Problem:** Embedding 3D WebGL runtimes directly in hero sections can inflate bundle size by 1.2MB+, driving Largest Contentful Paint (LCP) above 4.5 seconds on mobile networks.
- **Decision:** Encapsulated the 3D Spline viewer behind dynamic client-only imports triggered by `IntersectionObserver`. Mobile visitors see an optimized WebP static render initially; the interactive 3D model hydrates only when the user scrolls or interacts. This kept initial mobile LCP under 1.8 seconds.

### 2. Server Actions with Prisma vs. API Route Handlers
- **Decision:** Utilized Next.js 16 Server Actions to encapsulate mutations directly with database calls, eliminating redundant boilerplate API routes while ensuring end-to-end TypeScript type inference.
