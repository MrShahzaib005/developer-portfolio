## 01 / The Episode: The Enrollment Day Deadlock

During my 3rd semester at university, I built `e-portal` to automate course registration, fee slip generation, and attendance management. It was built as a traditional server-rendered Spring Boot MVC application backed by MySQL.

Everything functioned seamlessly in local testing with a single user. But on simulated semester registration day, when multiple students attempted to register for courses with limited seats simultaneously, the system encountered a severe failure:

```
[HTTP Request: Thread 42] -> Acquires pessimistic lock on Course(CS-301)
[HTTP Request: Thread 43] -> Waiting for lock...
[HTTP Request: Thread 44] -> Waiting for lock...
[Connection Pool Exhaustion] -> Timeout: 504 Gateway Timeout
```

Because course capacity was validated and decremented synchronously inside a heavy HTTP request-response cycle, concurrent requests caused database lock contention. The Tomcat thread pool exhausted itself, and the entire web application ground to a halt.

---

## 02 / The Realization & Architectural Shift

Fixing that mistake was the single most formative experience in my engineering journey:

1. **The Fragility of Synchronous Monoliths:** I realized that coupling user actions directly to synchronous relational table locks creates fragile software that fails precisely when usage spikes.
2. **Decoupling State from Transmission:** I redesigned the registration flow using queued state changes and optimistic version checks (`@Version` in JPA).
3. **The Bridge to Robotics:** More fundamentally, this episode demystified the illusion that software executes in a static, sequential world. Physical hardware and robotics are the ultimate asynchronous, concurrent environments: sensor feeds, motor PWM timers, and camera frames fire continuously at different frequencies. 

Understanding how to decouple state in Java prepared me directly for the asynchronous publish-subscribe model of **ROS 2 topics and middleware nodes**.

## 04 / Approach & Structural Lessons

```
[TRADITIONAL TIGHTLY-COUPLED MVC]
Browser Request ──> Controller ──> Synchronous DB Write ──> Response
(Fails under concurrent load; blocks threads)

          │  EVOLUTION & LESSON LEARNED
          ▼

[DECOUPLED EVENT-DRIVEN PATTERN]
Input Trigger ──> Memory Queue ──> Async Consumer ──> State Update
(The architectural foundation for both microservices and ROS 2 robotics)
```

## 05 / Reflection

Every senior engineer has a specific bug that made them serious about software architecture. For me, it was that enrollment deadlock in `e-portal`. It taught me that writing code that compiles is easy; designing systems that remain resilient when the world pushes against them is what engineering actually means.
