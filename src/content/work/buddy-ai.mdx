## 02 / The Core Problem: Small Parameter LLM Hazards

Deploying small parameter models (8B) in multi-user environments poses two critical vulnerabilities:

1. **Memory Leakage Across Tenants:** If a single global vector store is queried without strict identity filters, User A can retrieve private personal facts belonging to User B.
2. **Tool Over-Eagerness & Hallucination:** Small models frequently hallucinate JSON tool invocations during casual conversations, triggering unintended database mutations.

## 04 / Multi-Agent Separation & Sandboxing

```
[INCOMING HTTP REQUEST] (Bearer Token with User UUID)
  │
  ▼
[THREAD-LOCAL SECURITY FILTER]
Locks `userId` to current Java execution thread context
  │
  ▼
[THE ROUTER (CONTROLLER LAYER)]
Evaluates intent: Is this a simple conversation or a system tool trigger?
  │
  ├─ If Conversational:
  │    └─ [READ-ONLY RAG AGENT]
  │         Completely strips JSON tool schemas from payload.
  │         Appends `WHERE user_id = :currentThreadUser` to vector query.
  │         Generates natural language response via local Ollama.
  │
  └─ If Memory / Action:
       ├─ [MEMORY WRITER AGENT]
       │    Embeds text via Nomic-Embed-Text (768 dimensions).
       │    Persists vector tagged with active tenant ID.
       │
       └─ [ACTION AGENT]
            Executes authorized relational database operations.
```

## 05 / Key Technical Decisions

### 1. Dynamic Tenant Isolation via `ThreadLocal`
Instead of relying on the LLM to remember which user it is answering, tenant isolation is mathematically enforced at the PostgreSQL driver layer. The user ID is retrieved from the HTTP session header, attached to the current execution thread, and automatically injected into every pgvector cosine similarity search (`SELECT * FROM memories WHERE user_id = ? ORDER BY embedding <=> ? LIMIT 5`).

### 2. Prompt-Level Schema Sandboxing
Rather than providing tool schemas to every prompt, tools are dynamically removed from conversational prompts. This mathematically prevents the 8B model from executing unauthorized database writes during standard Q&A.
